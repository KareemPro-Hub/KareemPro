# إصلاح حذف العميل/المشروع مع حفظ المدفوعات —2026-10-24

- اشتكى كريم من React441 عند حذف صاحب مشروع. سجلا Vercel وPostgres أثبتا SQLSTATE23503: xpay_orders_client_id_fkey يمنع حذف العميل، وxpay_orders_stage_id_fkey يمنع حذف المشروع/المرحلة. لم يكن خطأ واجهة فقط.
- ترحيل preserve_xpay_history_on_delete يحوّل المرجعين الاختياريين إلى ON DELETE SET NULL. يبقى سجل Xpay ومبالغه وحالته وجلسته والأحداث محفوظة؛ لا تستخدم CASCADE لسجلات المدفوعات ولا تحذف العملية لتجاوز الخطأ. الفحص الفعلي كشف تداخل مساري SET NULL عند تعدد العمليات؛ ترحيل defer_xpay_owner_reference_checks يؤجل فحص المرجعين إلى نهاية المعاملة، بعد اكتمال كل المسارات. الحذف لا يتعطل بسبب وجود أي دفعة.
- deleteClient محمي requireAdmin ويتحقق من المعرف، يمنع حذف حساب المدير الحالي، ويتحقق من وجود عميل قبل استدعاء Auth. الأخطاء المتوقعة ترجع {ok:false,error:نص عربي} بدل خطأ خادم مخفي. النجاح يرجع {ok:true} ويحدّث نطاق الإدارة/البوابة؛ ClientActions يبقي القائمة عند الفشل ويحدّث العرض عند النجاح دون عرض تفاصيل React.
- بعد التشخيص قال كريم صراحةً «احذف دا عادي انا كنت عامله تجريبي». حُذف الحساب التجريبي المقصود ومشروعه فقط بمعاملة محكومة بهويته؛ تحقق داخلها من بقاء عملية Xpay بذات بصمة البيانات المالية مع تصفير المرجعين. لا يشمل التفويض أي عميل آخر. فحوص الواجهة وحد SDK معزولة، والفحص الإضافي للقواعد يستخدم بيانات مصطنعة مع إلغاء المعاملة كاملة.
