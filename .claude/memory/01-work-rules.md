# قواعد العمل — بالحرف كما قالها كريم

هذه ليست صياغة جديدة. كل سطر هنا نصٌّ قاله المالك داخل هذا المشروع.

## نطاق التعديل

> «التزم إنك تعدّل فقط الحاجة اللي فيها مشكلة أو المطلوبة فعلًا، من غير ما تلمس
> أو تغيّر أي كود تاني شغال كويس.»

> «لو محتاج تغيّر حاجة برا النطاق ده، قولي الأول قبل التنفيذ.»

> «وبعد كل تعديل، راجع واختبر الجزء ده والأجزاء المرتبطة بيه عشان تتأكد إن مفيش
> حاجة باظت.»

> «لا تصلح شيئًا غير مثبت أنه معطل، ولا تلمس كودًا يعمل جيدًا.»

> «لا تغيّر التصميم أو الألوان أو النصوص غير المرتبطة بالمطلوب.»

## Git والنشر

> «استخدم Git من الطرفية فقط، وممنوع استخدام GitHub Desktop.»

> «افحص Git والتغييرات قبل أي Commit.»

> «أضف الملفات المطلوبة فقط ولا تلمس تغييرات غير مرتبطة.»

> «نفّذ Commit واضحًا ثم Push إلى الفرع الصحيح بنفسك.»

> «لا تطلب من المستخدم تنفيذ Push يدويًا؛ نفّذه بنفسك ما لم يوجد عائق حقيقي خارج
> صلاحيتك.»

> «بعد Push نفّذ Fetch وتأكد أن HEAD مطابق للفرع البعيد، ثم تحقق من الإنتاج.»

> «لا تستخدم `git reset --hard` أو `git clean`، ولا تحذف أو تستبدل أي تغييرات
> موجودة.»

> «الفرع الصحيح هو `main`، ولا تستخدم الفرع القديم `nextjs-portal`.»

## الأسلوب واللغة

> «الردود تكون مختصرة وبسيطة وسهلة وباللغة العربية.»

> «ضع مسافة قبل علامتي الاستفهام والتعجب في العربية: `هل نبدأ ؟` و`ممتاز !`»

> «ضع التنوين على الحرف قبل الأخير، مثل `مالًا`.»

> «لا تستخدم Emoji كأيقونات داخل الواجهات؛ استخدم SVG نظيفة متناسقة مع الهوية.»

## الأمان

> «لا تعرض أو تحفظ كلمات مرور أو مفاتيح أو Tokens أو بيانات شخصية.»

## قاعدة مستخلصة من خطأ وقع فعلًا

قبل أي مراجعة واسعة أو «فحص شامل»، تحقق بـ `git log -S "<النص>"` أن ما تضيفه لم
يكن محذوفًا عمدًا من قبل. تفاصيل الحادثة في `06-decisions-and-fixes.md`.
