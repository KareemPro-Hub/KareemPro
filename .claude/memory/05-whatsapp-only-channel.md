# واتساب هي القناة الوحيدة

قرار المالك بتاريخ 2026-09-02: **لا يُرسل أي بريد إلكتروني لصاحب المشروع إطلاقًا.**

السبب كما قاله كريم: عملاؤه يأتون من الإعلانات إلى واتساب مباشرة، وكثير منهم لا
يفتح البريد أصلًا.

## كيف طُبِّق

- المفتاح `CLIENT_EMAILS_ENABLED = false` في `src/lib/email.js` يعطّل الدوال الست
  الموجّهة للعميل (رابط الدخول · طلب سداد · تأكيد استلام دفعة · تقدّم مرحلة ·
  ملف جديد · خصم). **لا تُفعّله ولا تلتف حوله.**
- `sendProposalDecisionEmail` و`sendClientNoteEmail` **تبقى شغّالة** — هذه
  إشعارات تصل لكريم نفسه لا للعميل.
- فورم «إضافة عميل جديد» بلا خانة بريد. الحساب يُنشأ بإيميل داخلي
  `<رقم الواتساب>@no-mail.kareempro.com` لأن Supabase لا يقبل حسابًا بلا إيميل —
  وهو معرّف فقط، لا يُرسل عليه شيء، ولا سجل MX للنطاق الفرعي.
- `contactLine(client)` في `src/lib/whatsapp.js` تعرض البريد الحقيقي للعملاء
  القدامى ورقم الواتساب لمن ليس لديه بريد. استخدمها في أي عرض لبيانات التواصل.

## دخول العميل

صاحب المشروع **لا يملك تبويبًا في شاشة الدخول** — شاشة `/login` للمدير وفريق
العمل فقط. دخوله حصريًا عبر رابط واتساب ذي استخدام واحد:

`login_tokens` (جدولنا) ← `/auth/enter` (درع ضد روبوتات المعاينة) ←
`/auth/enter/verify` ← جلسة Supabase ← `/portal`

هذا المسار **لا يلمس البريد إطلاقًا**؛ الإيميل مجرد معرّف والجلسة تُنشأ من السيرفر.

زائر غير مسجَّل يفتح `/portal` يُحوَّل للصفحة الرئيسية (لا لشاشة دخول الموظفين).

## معاينة الرابط على واتساب

روبوت المعاينة `facebookexternalhit` يحترم `robots.txt`. لذلك يوجد
`Allow: /auth/enter` **قبل** `Disallow: /auth` في `public/robots.txt`. لا تُزله
وإلا تختفي بطاقة المعاينة بالكامل.

**حجم صورة المعاينة شرط ثانٍ مستقل**: واتساب يُسقط الصورة من البطاقة بصمت إذا
تجاوزت `og:image` نحو **600 كيلوبايت** — تظهر البطاقة بلا بانر. حدث هذا فعلًا
حين كانت تشير إلى `og-banner-v2.png` (647 KB). المستخدم الآن
`public/og-banner-v2.jpg` — نفس التصميم، 1200×630، نحو 120 KB. أي بديل يجب أن
يبقى **تحت 300 KB وبصيغة JPEG**.

واتساب يخزّن المعاينة لكل رابط: رابط قديم يظل ببطاقته القديمة، والاختبار يكون
برابط دخول **جديد**.
